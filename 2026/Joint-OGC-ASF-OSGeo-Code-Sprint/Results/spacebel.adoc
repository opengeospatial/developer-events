== Spacebel results

The Spacebel D102 STAC Catalogue/OGC Records Catalogue was extended in the following ways :
 
. Added quality info (cloud cover) in ISO19115-3 (XML) metadata.  This metadata is available as STAC asset for items or via content negotiation.  Only collections in which the original OGC 17-003r2 metadata has cloudCover information have this information now encoded also in this ISO metadata format.  E.g. the TropForest collection at https://radiantearth.github.io/stac-browser/#/external/emc.spacebel.be/collections/TropForest.    Example product: https://radiantearth.github.io/stac-browser/#/external/emc.spacebel.be/collections/TropForest/items/KO2_OTPF_KO2_MSC_2F_20091121T032723_20091121T032723_017702_E096_N026?httpAccept=application%2Fgeo%2Bjson%3Bprofile%3Dhttps%3A%2F%2Fstacspec.org
. Added quality info (cloud covber) in  ISO19157-2 (XML) formats.  This metadata is available as STAC asset for items or via content negotiation. Only collections in which the original OGC 17-003r2 metadata has cloudCover information have this information now encoded also in this ISO metadata format.  Example product https://radiantearth.github.io/stac-browser/#/external/emc.spacebel.be/collections/TropForest/items/KO2_OTPF_KO2_MSC_2F_20091121T032723_20091121T032723_017702_E096_N026?httpAccept=application%2Fgeo%2Bjson%3Bprofile%3Dhttps%3A%2F%2Fstacspec.org
. Added same cloud cover quality example in GeoDCAT-AP response (i.e. all optical products that have cloud cover info in the catalogue now expose this as "quality info" in mentioned formats).   The W3C DQV encoding is used and the Metric objects use similar properties as available in OGC RAINBOW.   Is available for all products with cloud cover information.   Example: https://emc.spacebel.be/collections/TropForest/items/KO2_OTPF_KO2_MSC_2F_20091121T032723_20091121T032723_017702_E096_N026?httpAccept=application%2Fld%2Bjson%3Bprofile%3Dhttp%3A%2F%2Fdata.europa.eu%2F930%2F
. Tested several versions of "liability" STAC extension in cooperation with Lucio. Made recommendation to use same JSON encoding (version) for QA part as in ISO19115-4 json schemas. Partial backporting of JSON schemas from ISO repository from draft-2020 to draft-7 (STAC schema). Tested various versions with STACLint and STACBrowser.  The porting of the mdj.json and dqc.json files to JSON Schema Draft-7 and validation of both schemas was only completed after the Code Sprint on 07/02.  Ported ISO schemas were tested with the ajv-cli command-line validator.  Next step is to reuse these ported schemas in the STAC Liability Extension JSON schema proposed by 4113 Engineering to allow validation with STACBrowser and Staclint.com.
